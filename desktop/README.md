# 视频发布台

基于 Tauri 2、React 19 和 `social-auto-upload` CLI 的本地桌面工作台。Windows 安装包只提供桌面界面；发布引擎仍是本仓库的 Python 项目。

项目主页：[ytton/video-poster](https://github.com/ytton/video-poster)。

## 使用

1. 按上游 [`docs/install.md`](../docs/install.md) 安装仓库主线 CLI，确保项目目录内存在 `.venv/Scripts/sau.exe`、`.venv/Scripts/python.exe` 和 `conf.py`。
2. 启动桌面程序。如果 CLI 项目不在本机的开发目录，在标题栏“设置”中选择实际的仓库目录。
3. 在“账号”页添加账号别名并登录。B站登录会打开独立终端显示二维码；失败时终端会保留错误信息。账号会话仍保存在项目 `cookies/` 中。账号列表可从条目的非操作区域拖动排序，顺序保存在本机；外链入口可在系统浏览器打开对应平台后台或主页。
4. 在“发布”页将视频拖入接收框，或点击接收框选择文件；右侧可切换平台及视频 / 封面预览。标签支持中英文逗号。点击横竖封面可在设置弹窗中选帧、拖动裁切、缩放，点击“应用”会同时保存两种方向；也可直接拖入封面图片。标题、简介、封面和创作声明统一填写，默认声明为“原创 / 无需标注”。选账号后补齐显示的必填项；个别平台的声明可在“平台专属设置”中覆盖。
5. “作品管理”按视频文件 SHA-256 将同一份视频归为一部作品，保留首次填写的标题、简介、标签、封面及声明。只有发布任务成功结束的平台才计入“已发布”；点开作品可看各平台当次提交的字段和后台入口，并从原资料补发尚未成功发布的平台。补发前会重新核对文件哈希。任务页可查看 CLI 输出，其他 CLI 动作在“全部命令”页。

桌面端逐项执行发布任务。账号别名、任务及作品记录存在应用的 IndexedDB 中，不复制 Cookie。旧版任务记录没有视频路径和文案，无法反推文件哈希，因此从新版提交的视频开始形成作品档案。关闭程序会结束正在运行的 CLI 任务；若发布途中退出，请到平台核对最终状态。

## 开发与打包

需要 Node.js、pnpm、Rust、Windows WebView2 和已安装的主项目 CLI。在本目录运行：

```powershell
pnpm install
pnpm tauri dev
pnpm tauri build
```

`pnpm build` 检查 TypeScript 并构建前端。Windows 安装包位于 `src-tauri/target/release/bundle/nsis/`。

## 设计边界

- 桌面端直接启动当前仓库的 `sau`，平台上传与登录仍由原项目维护；CLI 帮助文档中的全部平台和动作会在“全部命令”页动态展示。
- 桌面端对支持 `--headed` 的动作始终显示浏览器窗口，包括视频发布和账号登录；CLI 不支持该参数的动作保持原有行为。B站视频上传通过 `biliup` 命令行工具执行，不显示网页发布表单。
- 通用封面与创作声明只传给 CLI 支持该字段的平台。知乎不支持自定义封面；微博现有上传器固定选择“二创”和“含AI生成内容”，勾选微博账号后须明确确认内容符合这两项声明。
- “只上传素材，不点发布”在 13 个网页上传平台填好发布页后停在发布按钮前，保持可见浏览器供人工检查；关闭浏览器结束任务。视频号使用保存草稿模式。B站通过 `biliup` CLI 上传，没有网页编辑页，开启此开关时不会入队。准备完成不会计入作品的已发布平台。
- `social-auto-upload` 的 TikTok 入口目前不在统一 `sau` CLI 中，因此桌面端也没有独立 TikTok 命令。
- 打包程序不附带 Python 运行时和浏览器驱动，须先安装主项目。账号登录与真实发布需要对应平台账号和网络环境；构建验收不会代替真实平台发布验收。
- B站命令行工具会按需下载；当 GitHub 最新发布只有桌面安装程序，或 API 暂时限流时，首次安装使用已确认可用的 `biliup-cli v1.3.4` 发布资源。
